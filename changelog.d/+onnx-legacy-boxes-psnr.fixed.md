`Boxes.to_mask`, `Boxes3D.to_mask`, `kornia.metrics.psnr`, `kornia.losses.psnr_loss` and `kornia.losses.PSNRLoss` export correctly with the legacy (TorchScript) ONNX exporter (`torch.onnx.export(..., dynamo=False)`) on torch 2.5.1, 2.9.1 and 2.14. Before, the two `to_mask` graphs had no input and returned an all-zero mask for any box: the legacy exporter traced the CPU loop and lost its in-place writes. Under the legacy exporter and `torch.jit.trace` they now compare a coordinate grid against the box bounds, as the dynamo exporter already did (and `Boxes.to_mask` on CUDA). The PSNR graphs returned a one-element vector of shape `(1,)` where eager returns a 0-d scalar; they now return the eager shape. `Boxes.to_mask` of an image with a side of 0, and `Boxes3D.to_mask` of such a volume, return an empty mask on the loop path (CPU, and CUDA for `Boxes3D`) as the grid path does, instead of raising `RuntimeError: cannot reshape tensor of 0 elements`. Every other eager result is unchanged.
