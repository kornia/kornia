`kornia.enhance.denormalize` and `Denormalize` return torch's default floating dtype (float32 unless changed with `torch.set_default_dtype`) for an integer or bool input, as `normalize` already did. They used to compute in and return the input's integer dtype, which was exact for integral statistics that did not overflow: `denormalize` of a uint8 `[0, 50, 100]` with `mean=10.0, std=2.0` returned uint8 `[10, 110, 210]` and now returns float32 `[10.0, 110.0, 210.0]`. Both functions now convert an integer input before applying `mean` and `std`, so under the default float32 an integer value above 2**24 is rounded first. Cast the result back, for example with `.round().clamp(0, 255).to(torch.uint8)`, where integer output is needed.
