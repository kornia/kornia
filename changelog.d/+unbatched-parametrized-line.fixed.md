`ParametrizedLine.point_at` on an unbatched `(D,)` line reads an `(N,)` `t` as `N` steps and returns `(N, D)` points, as it already did for `(N, 1)`. It used to multiply the steps with the direction element-wise, which returned one wrong point when `N` equalled `D`, a `(D,)` point for `N = 1`, and raised otherwise. `intersect` on an unbatched line with a batch of `M` planes therefore returns `M` points; it used to raise, or return one wrong point for `M = 3`. `line[i]` now returns the origin for `0` and `-2`, the direction for `1` and `-1`, and raises `IndexError` for any other index; it used to return the direction for every index but `0`.
