`find_essential` and `run_5point` no longer abort with `torch._C._LinAlgError` when a
correspondence set makes the 10x10 elimination matrix exactly singular, which happened for about 2%
of degenerate float32 inputs and for any set of points at a single location. The solver had a
damping fallback for this case, but it tested the result of `torch.linalg.solve` for NaN and
`torch.linalg.solve` raises on a singular batch element instead of returning NaN, so the fallback
was never reached. Singular elements are now flagged with `lu_factor_ex` and damped before the
solve; every other element goes through the same solve as before and its result is unchanged bit
for bit. `RANSAC(model_type="essential")` no longer propagates that error out of `forward` when a
minimal sample is degenerate. Fixes #4765.
