`FaceDetector` flips its input from RGB to BGR before YuNet, whose weights were trained on BGR images. It fed RGB, which found far fewer faces: run on the docs figure `yunet.jpg` as rendered before this change (421×1185, input and output panels together), the detector now returns 600 detections instead of 221, and 225 instead of 50 above a score of 0.6. The re-rendered figure's title reports 320 faces where it reported 228. The input stays RGB in [0, 255]; the bare `YuNet` takes BGR in [0, 255]. A caller that already passed BGR, for example a `cv2.imread` array, must now pass RGB, since the flip happens inside. An input that is not `(*, 3, H, W)`, such as a 1- or 4-channel or a channels-last image, raises a `ValueError` naming that shape from the flip; it raised a `RuntimeError` from inside YuNet. `EdgeDetectorBuilder` feeds DexiNed BGR in [0, 255] minus the BGR mean `[103.939, 116.779, 123.68]`, the input it was trained on, instead of RGB minus the ImageNet RGB mean; on two street photos this changed 8–11 % of the `p > 0.5` edge decisions. The input stays RGB in [0, 1]. `DexiNed` (`kornia.models.dexined` and `kornia.filters.dexined`) no longer raises a `RuntimeError` about an in-place operation in backward; its forward output is unchanged. `FaceDetectorResult` checks the last dimension of its data, so `(15,)` and `(N, 15)` are accepted and a row of fewer than 15 values raises `ValueError`. It checked the first dimension, so a `(3, 15)` tensor raised and a `(20, 14)` one was accepted until `.score` raised `IndexError`.
