`kornia.core.utils.dict_to_dataclass` now converts nested dicts in fields annotated `Optional[...]`, other unions,
`list`, `tuple` and `dict` of a dataclass, and in string annotations (including modules with
`from __future__ import annotations`), and keeps a value that is already an instance of the field's dataclass
instead of raising `TypeCheckError`. `ParametrizedLine`, `So2`, `Se2` and `Se3` given an integer or bool tensor now
raise `TypeCheckError` naming the field and its dtype, instead of torch's "Only Tensors of floating point and complex
dtype can require gradients" `RuntimeError`; cast the tensor to a floating-point dtype first. Under `torch.compile`,
`torch.jit.trace` and export they now raise too, where they used to keep the integer tensor as a plain attribute.
`Hyperplane` still stores integer coefficients as buffers. The API reference now renders the `kornia.core.utils`
device and autocast helpers that the `kornia.utils` deprecation warnings point to.
