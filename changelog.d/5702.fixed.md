`euler_from_quaternion` now returns a triple that represents the input rotation at gimbal lock (`pitch = ±pi/2`). There, `roll` and `yaw` used to come from `atan2(0, 0)`, so the triple did not match the input and the round trip through `quaternion_from_euler` was off by up to 2 in rotation-matrix entries. It now returns `pitch` exactly `±pi/2`, `roll` exactly `0` and the one determined combination in `yaw`, within `[-pi, pi]`; the input triple itself cannot be recovered at the pole. The gradient there is finite and small, where before it was of order 1e6 to 1e17 (and `nan` on older PyTorch), and rotations with `w = x = 0` (such as `yaw = pi`) keep a finite gradient on PyTorch 2.5.1 as well. Away from the pole nothing changes: outputs are bit-identical. A pitch within `2 * sqrt(eps)` of `±pi/2` is treated as gimbal lock and snapped to the pole. `Quaternion.to_euler` is fixed the same way.
