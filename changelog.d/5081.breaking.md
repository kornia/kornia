`kornia.morphology.dilation`, `erosion`, `opening`, `closing`, `gradient`, `top_hat` and `bottom_hat` now raise a `TypeError` for an image that is not floating point (`bool`, `uint8` or another integer dtype), before any padding or engine dispatch. Such images were never supported but used to run, with results that depended on the dtype, the border and the device: under the default `border_type="geodesic"`, `dilation` of a `bool` image on CPU set every border pixel, a `uint8` image raised torch's overflow `RuntimeError` on CPU and returned `240` at the border on MPS, and an integer image kept the finite `max_val` sentinel for excluded kernel cells, so `dilation` of `[0, 50000, 0]` by `[[1, 0, 1]]` returned `[50000, 40000, 50000]` instead of `[50000, 0, 50000]`. Floating-point images are unaffected. Convert an integer or boolean image with `.float()` first.
