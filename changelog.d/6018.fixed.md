`equalize_clahe` and `RandomClahe` now count, clip and accumulate the tile histograms of float16 and bfloat16 images in float32 on the default (fast) path, and cast only the finished lookup tables back. Before, with clipping enabled, a float16 image whose tiles hold about 65520 or more pixels, such as 2048 x 2048 with the default 8 x 8 grid, came back entirely NaN. Once the per-bin cap `clip_limit * tile_pixels // 256` passed 65504, `equalize_clahe` raised an overflow error on a float16 image instead (and aborted the process on MPS); at the default `clip_limit=40.0` that is any tile above about 419,000 pixels, such as the 8 x 8 grid of a 7680 x 4320 image. Smaller half-precision tiles got lookup tables one or more gray levels off in float16 and several in bfloat16. The lookup tables now equal those of a float32 image that holds the 8-bit levels the lookup reads, `(x * 255).long()` in the image dtype. float32 and float64 results, and the `slow_and_differentiable` path, are unchanged.
