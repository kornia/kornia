`KMeans.fit` no longer synchronises with the device once per cluster per iteration to update centroids; the update is now vectorised. This mainly benefits GPU backends where the per-cluster host syncs were expensive (e.g. MPS); on CPU the win is smaller and shrinks further at larger problem sizes, where the O(N·K·D) distance computation dominates. A fit that hits an empty cluster may now produce different (but equally valid) centers for the same seed, since the random reseed draws differ from before. Two more observable side effects of the old in-place update are also gone: `fit` no longer mutates a `cluster_centers` tensor passed in at construction, and calling `fit` a second time no longer warm-starts from the first call's result - neither was documented behavior, but code relying on either will now see a difference.
