`Boxes(corners)`, `Boxes.data`, `VideoBoxes.from_tensor` and `Boxes3D(corners)` now use exclusive corners, one pixel beyond the last pixel: a box `[x1, x2)` that was given as inclusive corners `(x1, x2 - 1)` is now given as `(x1, x2)`. The default `Boxes(...)` export label is `'vertices'` instead of `'vertices_plus'`, so `Boxes(corners).to_tensor()` still returns `corners`. Pass `to_tensor('vertices_plus')` where inclusive corners are needed: to a tensor under the `"bbox"` key, or to `infer_bbox_shape` and `bbox_to_mask`, which take one box per image, as the export of an unbatched `Boxes`, `(N, 4, 2)`; `Boxes.to_mask` draws several boxes per image. `Boxes.transform_boxes` reads its matrix on pixel centres, as kornia's image matrices are, so a matrix written for box coordinates gives other numbers: `diag(2, 2, 1)` now maps the box `[10, 30)` to `[19.5, 59.5)`, where it gave `[20, 59)` before. Pass such a matrix, for example a resolution change or a normalized-to-pixel scale, as `T(-1/2) M T(+1/2)`, or scale the `to_tensor('xyxy')` export instead. `Boxes3D.transform_boxes` applies its matrix to these exclusive corners as given, so a 2x scale of `[0, 2]` gives `[0, 4]`. A bfloat16 or float16 box in `'xyxy_plus'` or `'xywh'` mode whose width or height rounds to zero at its position, such as bfloat16 `xywh=[256, 0, 1, 1]`, now raises `ValueError`; import it in float32. `from_tensor` builds a list of boxes in several dtypes in their promoted dtype, as `torch.cat` would, instead of the first box's dtype. Objects pickled with earlier releases load with their old storage and numbers; combining one with a new object raises `ValueError`.
