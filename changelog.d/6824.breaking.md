`Boxes(corners)`, `Boxes.data`, `VideoBoxes.from_tensor` and `Boxes3D(corners)` now use exclusive corners, one pixel beyond the last pixel: a box `[x1, x2)` that was given as inclusive corners `(x1, x2 - 1)` is now given as `(x1, x2)`. The default `Boxes(...)` export label is `'vertices'` instead of `'vertices_plus'`, so `Boxes(corners).to_tensor()` still returns `corners`. Pass `to_tensor('vertices_plus')` where inclusive corners are needed, for example to the `kornia.geometry.bbox` helpers or to a tensor under the `"bbox"` key. `Boxes3D.transform_boxes` applies its matrix to these exclusive corners as given, so a 2x scale of `[0, 2]` gives `[0, 4]`. A bfloat16 or float16 box in `'xyxy_plus'` or `'xywh'` mode whose width or height rounds to zero at its position, such as bfloat16 `xywh=[256, 0, 1, 1]`, now raises `ValueError`; import it in float32. Objects pickled with earlier releases load with their old storage and numbers; combining one with a new object raises `ValueError`.
