`kornia.augmentation.RandomPlanckianJitter` no longer upcasts float16/bfloat16 input to float32.
`apply_transform` indexed the registered `pl` (Planckian-locus color coefficient) buffer with
`.to(device=input.device)` but no `dtype=`; the buffer stays at its own construction-time float32
dtype unless the whole module is explicitly `.to(dtype=...)`'d, so `input * r_w` silently promoted
a float16/bfloat16 batch through ordinary PyTorch type promotion. Found via a systematic
dtype-preservation sweep of all 45 constructible `Random*` augmentations; `RandomDissolving` leaks
the same way through an internal Stable Diffusion pipeline and is a separate, heavier fix, not
addressed here.
