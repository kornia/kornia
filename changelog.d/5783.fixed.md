`fit_plane` now fits float16 and bfloat16 points in float32 and returns the plane in the input dtype. It used to fit them in their own dtype: a float16 point cloud in millimetres, such as a depth frame, was rejected as collinear because the largest singular value, which grows with the square root of the number of points times their spread, overflowed float16 (#5821), and half-precision offsets lost bits to cancellation (float16 returned -18.5 and bfloat16 -18.0 for an offset of -18.475). The collinearity test keeps the input dtype's tolerance but now applies it to the given points rather than to their half-precision centring, so a near-collinear half-precision set that this rounding let through now raises `ValueCheckError`. float32 and float64 results are unchanged.
