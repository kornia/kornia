`camtoworld_to_worldtocam_Rt`, `worldtocam_to_camtoworld_Rt`, `camtoworld_graphics_to_vision_4x4` and `camtoworld_vision_to_graphics_4x4` now return a result in the input's dtype for `uint8`, `int8`, `int16`, `int32` and `int64` input on CUDA, as they already did on the CPU and MPS. CUDA has no integer matrix multiplication, so these functions used to raise `NotImplementedError: "baddbmm_cuda" not implemented for 'Long'` (or the matching error for another integer dtype) there.
