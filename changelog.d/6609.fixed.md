`PatchDominantGradientOrientation`, `SIFTDescriptor`, `DenseSIFTDescriptor` and `SIFTDescriptorFromPyramid` no longer take gradients and angles from convolution rounding on the flat pixels of tracked input: `sq > 0` read exactness from a convolution result. A constant 0.1 patch on x86 CPU or CUDA now has a zero gradient. The large change is on macOS arm64 CPU for a grad-enabled float32 batch of 16 or more, where the gradients of low-contrast patches come down by orders of magnitude, and a float16 low-contrast patch no longer gets an `inf` or NaN gradient from `PatchDominantGradientOrientation`. Calls under `torch.no_grad()` and calls on an untracked patch or image are unchanged, except for `SIFTFeature` with the patch backend in default grad mode, whose descriptors on macOS arm64 CPU move closer to the `torch.no_grad()` ones with the same Oxford matching accuracy.
