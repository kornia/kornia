`MS_SSIMLoss` now requires `img1` and `img2` to be 4-D `(B, C, H, W)` tensors of the same shape, as `SSIMLoss` does, and raises `ValueError` otherwise (a `ShapeError` for a shape mismatch), also with Kornia checks disabled (#6157). It used to compare only the number of dimensions. An image with batch size 1 was broadcast over the batch of the other one and returned the loss against the repeated image, with only a torch warning; callers that relied on this must expand the image themselves. A height or width of 1 was broadcast too and returned a wrong loss, and so did some 3-D `(C, H, W)` pairs. Inputs of different ranks already raised `ValueError`; every other mismatch or input that is not 4-D ended in a torch `RuntimeError` or `IndexError` and now raises `ValueError`, which `except RuntimeError` does not catch.
