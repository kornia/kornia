`EfficientViT.from_config` now loads the pretrained backbone weights: the hosted checkpoints store them under a `backbone.` prefix, which the previous non-strict load silently dropped, so every "pretrained" model was randomly initialised. The load is now strict: a checkpoint whose backbone entries do not match the model raises `RuntimeError` instead of returning a partly loaded model. A state dict saved from the backbone itself, without the prefix, still loads.
