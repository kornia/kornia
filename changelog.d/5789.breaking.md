`CenterCrop3D` and `RandomCrop3D` now report invalid crop sizes with the `size` argument and supplied value. Malformed size sequences raise `TypeError` instead of an indexing or internal tensor-shape error; `RandomCrop3D` also rejects unsupported size types and non-integer sequence elements at construction, instead of failing later in parameter generation or grid sampling. Pass a three-element tuple or list of integers to `RandomCrop3D`. `CenterCrop3D` rejects tuples with extra elements rather than silently ignoring them, and now rejects non-integer tuple elements at construction instead of accepting them and failing later when applying the crop. Pass exactly three integers `(D, H, W)`. Oversized crops now raise `ValueError` in both classes (previously `AssertionError` in `CenterCrop3D`) and report the requested and input spatial sizes. `CenterCrop3D(n)` remains supported; `RandomCrop3D(n)` remains unsupported and requires `(n, n, n)`.
