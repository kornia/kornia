`kornia.morphology.dilation`, `erosion`, and the functions built on them (`opening`, `closing`, `gradient`, `top_hat`, `bottom_hat`) now compute `engine="convolution"` in the same promoted dtype as `engine="unfold"` and `engine="shift"`. Previously, `engine="convolution"` returned the image's own dtype for a mismatched-dtype kernel or `structuring_element` (for example, a float16 image with a float32 kernel returned float16), while the other two engines promoted to the wider dtype (float32) — so switching `engine` silently changed the result dtype. All three engines now agree.
