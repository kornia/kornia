`find_essential` solves in float64 (float32 on MPS) whatever the input dtype, so a float32 five-point sample no longer misses the true essential matrix (#4884). Its roots come from the host for every device, detached, with a Newton step that supplies their gradient, so `backward` no longer raises at a multiple root (#4903) nor returns NaN gradients for samples without parallax (#4952), and repeated calls on CUDA return identical results. A five-point sample with rank-deficient constraints returns ten NaN candidates and a zero gradient. At 2048 samples it takes 27 ms instead of 41 ms on CPU and 21 ms instead of 28 ms on CUDA.
