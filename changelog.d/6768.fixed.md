`rgb_to_xyz`, `xyz_to_rgb`, `rgb_to_yuv`, `yuv_to_rgb`, and the conversions built on them (`rgb_to_lab`, `lab_to_rgb`, `rgb_to_luv`, `luv_to_rgb` and their module forms) compute float32 images in float32 on CUDA with PyTorch's default precision settings. Off the CPU they applied their 3x3 color matrix as a 1x1 `conv2d`, which follows cuDNN's TF32 switch, on by default in PyTorch, and cuDNN chose the precision per shape: one `(1, 3, 224, 224)` image, and every shape under `torch.compile`, came back with a 10-bit mantissa (3.6e-4 error in `rgb_to_xyz`, 5.9e-2 in `rgb_to_lab`, 8.5e-4 in an RGB to YUV round trip), while other shapes got float32. The matrix is now applied with one matmul on every device, which follows `torch.backends.cuda.matmul.allow_tf32` (off by default) like any other matrix product. CPU results are bitwise unchanged.
