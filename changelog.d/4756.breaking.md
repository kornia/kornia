`crop_by_indices` now honors `shape_compensation` when every box in the batch is identical. With a `shape_compensation` other than `"resize"` and a slice that does not match `size`, it used to resize the slice to `size` whenever all boxes in the batch coincided (always for a batch of one) and zero-pad or trim it otherwise; it now zero-pads or trims it in both cases, so a row's output no longer depends on the other rows in the batch. `RandomMosaic(cropping_mode="slice")` crops this way (`shape_compensation="F.pad"`): for a batch of one, or any batch whose crop boxes coincide, a crop that does not match `output_size` (for example because `output_size` differs from the input size) used to be resized to `output_size`, out of register with the transformed boxes; it is now zero-padded or trimmed at the bottom and right, as batches with differing boxes already were, so fixed-seed outputs change.
