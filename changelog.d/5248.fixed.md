`check_safetensors` and `load_safetensors` now raise the documented `ValueError`, naming the file, for several malformed headers that used to escape it. Previously a `dtype` given as a JSON list or object raised `TypeError`, a deeply nested header raised `RecursionError`, and an integer too long for Python to decode, or a shape whose byte size was too large to print, raised a `ValueError` that did not name the file. A shape of many large dimensions is now rejected in linear time, where multiplying it out took about a minute for 100 000 dimensions, and error messages quote header values in shortened form. `check_safetensors` now also rejects any empty tensor shape that torch cannot build, such as `[2**63, 0]` or `[0, 2**62, 2**62]`, so `load_safetensors` can load, on the CPU, every file the check accepts. The header is still not validated beyond what the reader uses: the optional `__metadata__` entry is ignored whatever it holds, and when a key appears twice the last one wins.
