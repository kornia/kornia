`equalize_clahe` and `RandomClahe` now blend neighbouring tile lookup tables with weight steps of `1 / tile_size`, instead of `1 / (tile_size - 1)`, anchored at each tile's actual centre. This changes interpolated output values in both the fast and differentiable paths. Kornia intentionally anchors the blend half a pixel before OpenCV/scikit-image's historical phase to preserve flip symmetry on unpadded grids. For the same tiles and lookup tables, the phase difference is at most half an interpolation step per axis; exact `cv2.createCLAHE` parity is not the contract. Border regions still clamp to the nearest tile along the border axis. LUT calculation and quantization are unchanged; Kornia's existing even-tile sizing and padding can cause additional differences from OpenCV.
