`kornia.geometry.subpix.render_gaussian2d` no longer distorts the rendered Gaussian's peak
location for `width`/`height` beyond 2048 on a float16 input. The internal pixel-coordinate
linspace used to be built at `dtype`; float16 can only exactly represent integers up to 2048
(`torch.linspace(0, 2199, 2200, dtype=torch.float16)` has only 2124 distinct values, not 2200),
so distinct coordinates silently collapsed together near the top of a large grid. The coordinate
grid and downstream Gaussian computation now run at float32 internally whenever the caller's
dtype is float16/bfloat16, with the returned heatmap explicitly cast back to that original dtype
at the end.
