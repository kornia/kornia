`kornia.geometry.subpix.render_gaussian2d` no longer distorts the rendered Gaussian's peak location on large grids for `float16` and `bfloat16` inputs. The pixel-coordinate linspace was built at the input dtype, so distinct coordinates collapsed together once `width`/`height` exceeded what the dtype represents exactly: about 2048 for `float16` and about 256 for `bfloat16`. The coordinate vectors are now built at `float32` for half-precision inputs, and the result is returned in the original dtype. Half-precision outputs of this function change bitwise (in a random-input check against the previous code every grid from 5x7 up differed, and a 1x1 grid did not), so stored regression baselines for half-precision inputs need regenerating.
