`kornia.geometry.subpix.render_gaussian2d` no longer distorts the rendered Gaussian's peak location on large grids for `float16` and `bfloat16` inputs. The pixel-coordinate linspace was built at the input dtype, so distinct coordinates collapsed together once `width`/`height` exceeded what the dtype represents exactly: about 2048 for `float16` and about 256 for `bfloat16`. The coordinate vectors are now built at `float32` for half-precision inputs, and the result is returned in the original dtype. All `float16`/`bfloat16` outputs of this function change bitwise, so stored regression baselines for half-precision inputs need regenerating.
