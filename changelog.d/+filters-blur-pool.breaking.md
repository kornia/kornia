`blur_pool2d`, `BlurPool2D`, `max_blur_pool2d` and `MaxBlurPool2D` with an even `kernel_size` now return `ceil(H / stride)` rows and `ceil(W / stride)` columns (`ceil((H - max_pool_size + 1) / stride)` and `ceil((W - max_pool_size + 1) / stride)` for the max variants), the size an odd `kernel_size` already returned (#5166). The input is zero-padded by `(k - 1) // 2` pixels before and `k // 2` after along each axis, as in antialiased-cnns' `BlurPool` with `pad_type='zero'`. Previously both sides were padded by `(k - 1) // 2`, one pixel too few for an even kernel, so the output lost its last row and column: a 7x10 map returned 6x9 at stride 1, 3x5 at stride 2 and 2x3 at stride 3, where it now returns 7x10, 4x5 and 3x4, and `max_blur_pool2d(x, 4, stride=1, max_pool_size=1)` on an 8x8 map returned 7x7 where it now returns 8x8. The old output is the leading block of the new one. Odd kernel sizes are unchanged, bit for bit. The Shape formulas in the docstrings state the new sizes.
