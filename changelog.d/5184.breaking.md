`blur_pool2d`, `BlurPool2D`, `max_blur_pool2d` and `MaxBlurPool2D` now return `ceil(H / stride)` rows and
`ceil(W / stride)` columns for every kernel size (`ceil((H - max_pool_size + 1) / stride)` for the max variants), as
antialiased-cnns does: the input is zero-padded by `(k - 1) // 2` pixels before and `k // 2` after along each axis
(#5166). Previously both sides were padded by `(k - 1) // 2`, one pixel too few for an even kernel size, and the output
lost its last row and column: a 7x10 map returned 6x9 at stride 1 and 3x5 at stride 2 with a kernel size of 2, 4 or 6,
where it now returns 7x10 and 4x5, and `max_blur_pool2d(x, 4, stride=1, max_pool_size=1)` on 8x8 returned 7x7 where it
now returns 8x8. The old output is the leading block of the new one. Odd kernel sizes are unchanged and bitwise
identical. `edge_aware_blur_pool2d` and `EdgeAwareBlurPool2D` with an even kernel size now run and keep the input
shape instead of raising a shape error. The Shape formulas in the docstrings state the new sizes.
