The `kornia.morphology` functions (`dilation`, `erosion`, `opening`, `closing`, `gradient`, `top_hat`, `bottom_hat`) now default to `engine="auto"` instead of `"unfold"`. `"auto"` runs `"unfold"` on CUDA; off CUDA it runs the exact `"shift"` engine, except that a CPU call which computes in float32 or float64 (the image dtype, or the wider dtype a kernel or structuring element promotes it to) and records a backward graph keeps `"unfold"`. For finite inputs the forward output remains equal to `"unfold"` (`torch.equal`), including mixed-dtype kernels and non-flat structuring elements; only the sign of a zero can differ, because a backend's `max`/`min` may return either tied operand. Gradients change only where `"shift"` is now selected: CPU float16/bfloat16, MPS, and forward-mode AD (`torch.func.jvp`) off CUDA, which records no backward graph. Previously a window with tied maxima sent its whole gradient to one argmax; `"shift"` splits it across the tied inputs, so pixels that received exactly zero can now receive a fraction (the total is unchanged). Pass `engine="unfold"` to keep the previous gradient behaviour.
