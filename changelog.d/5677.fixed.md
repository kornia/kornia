`ScaleSpaceDetector` now places each detection where its octave pixel lies in the input image. It used to scale octave coordinates by the nominal spacing `2**o`, but `ScalePyramid` resizes with `align_corners=True`, which maps octave pixel `u` to input pixel `u * (W - 1) / (W_o - 1)` and the same along `y`. Detections from a doubled first octave were up to half a pixel too far from the origin. Detections from every coarser octave were pulled towards the origin, by several pixels on large images. `HesAffNetHardNet`, `GFTTAffNetHardNet` and `SIFTFeatureScaleSpace` (with its default `"patch"` backend) are affected. The `ScalePyramid` documentation now states the map and that `pixel_dists` is nominal.
