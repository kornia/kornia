`Resize`, `LongestMaxSize`, `SmallestMaxSize` and slice-mode `RandomResizedCrop` with `resample="nearest"` now resize with PyTorch's `nearest-exact` grid, which copies source column `floor((u + 0.5) * W_in / W_out)` into output column `u`, and record the matching half-pixel `transform_matrix`, `x' = (x + 0.5) * W_out / W_in - 0.5` (likewise for `y`). Previously they copied the legacy `floor(u * W_in / W_out)` column and recorded a corner-to-corner matrix that the image did not follow, so keypoints and boxes landed up to one output pixel away from the pixels they belong to (#5293). Nearest-resized images and the recorded matrices change. So do masks resized by these augmentations in `AugmentationSequential`, which resamples masks with nearest even when images use bilinear.
