`kornia.enhance.normalize`, `denormalize` and the `Normalize`/`Denormalize` modules no longer cast `mean` and `std` to an integer input's dtype. For a uint8 image a fractional statistic truncated to 0, so `normalize(x, 0.5, 0.5)` returned `nan`/`inf`, and the arithmetic wrapped around in the integer dtype: `normalize([0, 128, 255], 100.0, 50.0)` returned `[3.12, 0.56, 3.10]` instead of `[-2.0, 0.56, 3.1]`, and `denormalize([0, 128, 255], 10.0, 2.0)` returned `[10, 10, 8]` instead of `[10, 266, 520]`. An integer or bool input is now converted to torch's default floating dtype first; a bool input, which used to raise `NotImplementedError`, is accepted. Floating and complex inputs are unchanged, and pixel values are not rescaled: give `mean` and `std` in the 0-255 scale for a uint8 image.
