`HomographyTracker` tracks with `float16` and `bfloat16` matchers. The second frame raised: in `warp_perspective`, which got the half frame with the float32 inverse of the first frame's float32 homography, or in `linalg.inv` for a half `previous_homography`. The prior is now inverted and the frame warped in float32, and the fast matcher gets the warped frame in the frame's dtype. `no_match()` and every homography the tracker returns or stores are float32 for a half target (`no_match()` returned the half dtype), and have the target's dtype otherwise, so a `float64` tracker whose matcher returns float32 keypoints returns float64 homographies where it returned float32 ones.
