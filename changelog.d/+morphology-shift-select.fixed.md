The `shift` morphology engine (the default forward-only CPU engine) reads each kernel cell from a two-plane buffer through `index_select` instead of masking every shifted view with `masked_fill_`, and skips the offset addition when no `structuring_element` is given. Results are bitwise unchanged; `dilation` and `erosion` of a `1 x 3 x 256 x 256` float32 image run about 1.6 to 2.2 times faster than after #4818 on CPU, back to within 10 to 50 % of the pre-#4818 speed depending on the kernel size.
