`Rt_to_matrix4x4`, `camtoworld_graphics_to_vision_Rt` and `camtoworld_vision_to_graphics_Rt` raise `ValueError` naming the dtype when `R` and `t` promote to an integer or boolean dtype. They used to raise torch's `RuntimeError: result type Float can't be cast to the desired output type Long` (or `Int`, `Bool`, ...) from inside the 3x4 to 4x4 homography conversion, so code that caught that `RuntimeError` has to catch `ValueError` now. Pairs that promote to a floating point or complex dtype, mixed integer/floating pairs included, return the same matrices as before.
