`crop_by_indices` joins the per-row crops with one `torch.cat` when every row's slice already matches `size`, instead of a `copy_` per row (#4531): one copy kernel per batch instead of one per sample, with the same values and the same default memory format. `RandomCrop` in slice mode always takes this path; rows that need `shape_compensation` still go through the per-row loop, and MPS keeps the per-row copies, which are faster there. A list `size`, as `RandomCrop([h, w])` passes it, no longer resizes every row to its own size.
