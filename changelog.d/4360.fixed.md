`kornia.enhance.image_histogram2d` no longer collapses distinct bins together at large `n_bins`
on a float16/bfloat16 input, and preserves that input's dtype in its `hist`/`pdf` return values.
The auto-constructed bin centers used to be built at `image.dtype`; float16 can only exactly
represent integers up to 2048 (`torch.arange(4096, dtype=torch.float16)` has only 3073 distinct
values, not 4096), so different bin indices silently landed on the same center and produced
numerically identical (redundant) histogram output once `n_bins` was large enough. Centers are
now always built at float32 internally, with the public `hist`/`pdf` outputs explicitly cast back
to the caller's original dtype at the return boundary so this precision fix does not itself
change the function's return dtype.
