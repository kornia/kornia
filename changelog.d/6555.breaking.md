`Normalize`, `Denormalize` and `Rescale` keep a constructor argument passed as `torch.nn.Parameter` as a registered parameter again, so `module.parameters()` and `state_dict()` include it, and `torch.export` and ONNX export work. In 0.9.0 it became a non-persistent buffer: an optimizer built from `module.parameters()` skipped it and both exports raised. Checkpoints saved by 0.8.x with such an argument load again. A checkpoint saved by 0.9.0 with such an argument has no entry for it, so strict loading now raises a missing-key error, and `strict=False` keeps the constructor's value. Optimizer state saved by 0.9.0 for such a model holds fewer parameters and raises `ValueError` on load. Ordinary tensor arguments stay non-persistent buffers.
