`RandomCrop3D` no longer accepts a crop exactly one voxel larger than the (padded) input along an axis. It used to pass the size guard, crop past the edge and return a volume with an empty slab; it now raises the same `ValueError` that a larger crop already did. `RandomCrop` and `RandomCrop3D` also honour a `fill` sequence holding one value per channel, which both have always documented but which raised `TypeError: pad(): argument 'value' must be float, not tuple`; a sequence must match the channel count and requires `padding_mode="constant"`.
