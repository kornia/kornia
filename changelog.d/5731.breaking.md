`DISK` and `kornia.feature.disk.detector.heatmap_to_keypoints` now raise a `ValueError` naming the odd-size requirement when `window_size` is even, as the reference implementation (cvlab-epfl/disk) does, because an even window has no centre pixel. Previously an even `window_size` was accepted and the non-maxima suppression ran an off-centre window (one pixel fewer before the candidate than after it), so the keypoints it returned were not the maxima of a window around them. The default `window_size=5` and every other odd size are still accepted; with them only maxima within `window_size // 2` pixels of the border and equal maxima in a window are handled differently, as the bug-fix entry describes.
