The model `DepthAnythingONNXBuilder.build` returns resizes each image to the size transformers' `DPTImageProcessor` computes from the model's `preprocessor_config.json`: it keeps the aspect ratio, fitting the side whose scale is closer to 1, and makes each side a multiple of 14. The filter is an antialiased bicubic, the one of transformers' fast `DPTImageProcessorFast` (`torch.nn.functional.interpolate(..., antialias=True)`), which approximates the slow processor's PIL resize. Every image used to be squashed to 518 x 518 with a bilinear resize without antialiasing, so a 16:9 frame was squeezed 1.78x horizontally before the network saw it; a 300 x 400 image now reaches the network at 392 x 518, and a 1080 x 1920 frame at 518 x 924. Every image other than 518 x 518 is now resized by this rule and filter, so its depth changes. The config parser behind it reads `keep_aspect_ratio`, `ensure_multiple_of` and `resample` (PIL's nearest, bilinear or bicubic), with the processor's defaults (`False`, `1`, bicubic) when they are absent, and raises `NotImplementedError` for any other `resample` filter, which it used to replace with bilinear. `DepthEstimation` accepts images of any floating dtype: it runs the graph in float32 and returns the depth in the image's dtype, where a float64, float16 or bfloat16 image raised inside ONNX Runtime or NumPy. An integer image raises kornia's `BaseError` instead of ONNX Runtime's `InvalidArgument`. `DepthEstimation.visualize` and `save` accept a tensor batch, on which they raised `ValueError`.
