`DepthAnythingONNXBuilder.build` resizes the image as transformers' `DPTImageProcessor` does with the model's `preprocessor_config.json`: it keeps the aspect ratio, fitting the side whose scale is closer to 1, makes each side a multiple of 14, and resizes bicubically (with antialiasing when it downscales). Every image used to be squashed to 518 x 518 with a bilinear resize, so a 16:9 frame was squeezed 1.78x horizontally before the network saw it; a 300 x 400 image now reaches the network at 392 x 518, and a 1080 x 1920 frame at 518 x 924. Depth values change for every non-square input. The config parser behind it reads `keep_aspect_ratio`, `ensure_multiple_of` and `resample`, with the processor's defaults (`False`, `1`, bicubic) when they are absent, and raises `NotImplementedError` for a `resample` filter other than nearest, bilinear or bicubic, which it used to replace with bilinear. `DepthEstimation` accepts images of any floating dtype: it runs the graph in float32 and returns the depth in the image's dtype, where a float64, float16 or bfloat16 image raised inside ONNX Runtime or NumPy. An integer image raises kornia's `BaseError` instead of ONNX Runtime's `InvalidArgument`. `DepthEstimation.visualize` and `save` accept a tensor batch, on which they raised `ValueError`.
