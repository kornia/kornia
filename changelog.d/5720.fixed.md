`LoFTR("indoor_new")` no longer switches every LoFTR created afterwards in the same process to the `indoor_new` positional encoding. It used to write `temp_bug_fix = True` into the shared module-level `default_cfg` (and into a config dict passed by the caller), so a later `LoFTR("outdoor")` ran with the wrong positional encoding and matched almost nothing. Each `LoFTR` now works on its own deep copy of the config.
