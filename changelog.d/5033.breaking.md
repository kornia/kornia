`save_pointcloud_ply` and `save_pointcloud_ply_binary` now write every row of the flattened input, including rows whose x, y and z are all non-finite (written as `nan` / `inf` in ASCII and as IEEE values in binary), so the `element vertex` count equals the number of points and row `i` of the file is row `i` of the input. Previously such rows were silently skipped and the vertex count excluded them, which broke the row-to-pixel correspondence of an organised cloud such as `depth_to_3d` output with invalid depth.
