`determinant_to_polynomial` now evaluates float16 and bfloat16 inputs in float32 and returns the input dtype. It used to
sum the coefficients in the half dtype, so on CUDA and MPS two calls on the same input could return coefficients that
differed far beyond the half dtype's rounding (0.21 in bfloat16 on CUDA, 0.75 on MPS). The float32 sum leaves only
float32 roundoff, which can still change a coefficient by one half-precision step after the cast.
