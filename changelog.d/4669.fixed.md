`solve_quartic` no longer returns values that are not roots of the quartic it was given. When the
resolvent cubic has a near-double root, `solve_cubic` can lose it, and Ferrari then factored a
different polynomial and reported its roots: `(x^2 + 2x + 5)(x^2 + 2x + 5.01)`, which has no real
roots, came back as `[1.0012, -3.0012, 1.0012, -3.0012]` with a residual of 64. Each returned root is
now checked against the quartic and replaced with the existing zero placeholder for "no real root" if
it does not satisfy it. Measured over 2000-row sweeps per family with ground truth from `numpy.roots`,
this removes 844 of 844 float32 rows and 319 of 319 float64 rows that returned spurious roots, while
leaving the number of rows that lose genuine real roots unchanged in every family and both dtypes.
Affects float64 as well as float32. Fixes #4474.
