`get_tps_transform` now solves Bookstein's thin-plate spline, with the radial kernels on its first argument, where the spline interpolates, so `warp_points_tps`, `warp_image_tps` and `RandomThinPlateSpline` match scipy's `RBFInterpolator(kernel="thin_plate_spline", degree=1)`. It used to centre the kernels on its second argument, which left the warp off between the landmarks by about a third of the displacement on six random landmarks, and growing like `r log r` away from them. This is a correctness fix under the stability policy's escape hatch, without a deprecation window, and existing calls need one change that no error will point out: pass the first argument of `get_tps_transform` as `kernel_centers`, so `warp_points_tps(pts, points_src, kw, aw)` after `get_tps_transform(points_src, points_dst)` and `warp_image_tps(img, points_dst, kw, aw)` after `get_tps_transform(points_dst, points_src)`. The old `warp_points_tps(pts, points_dst, kw, aw)` and `warp_image_tps(img, points_src, kw, aw)` still run but now return a wrong warp that misses the landmarks; `kw.mT @ kernel_centers` is zero up to round-off only for the right centres. Weights fitted before this change keep giving the old warp with the old centres, and `RandomThinPlateSpline` returns a different image for the same seed or `params` unless `scale=0`. A constant map, which used to be singular, now fits with zero kernel weights.
