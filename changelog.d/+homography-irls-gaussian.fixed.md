`find_homography_dlt_iterated` and `find_homography_lines_dlt_iterated` re-weighted each correspondence with `exp(-e / (2 * soft_inl_th**2))` of the unsquared error `e`, a kernel in which `soft_inl_th` had no pixel meaning (#4870). They now use the Gaussian `exp(-e**2 / (2 * soft_inl_th**2))`, so `soft_inl_th` is a standard deviation in pixels, and `RANSAC`'s homography polishers set it to `inl_th`. Polished homographies change accordingly.\n
