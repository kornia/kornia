On CPU, float16 and bfloat16 warps no longer return corrupted values (NaN, values up to 3.4e38, and in bfloat16 a sampling grid off by more than half a pixel) on images of about 128 px and more. `warp_affine`, `warp_perspective`, `remap`, `warp_affine3d`, `warp_perspective3d`, `homography_warp3d`, `homography_warp` with a pixel homography, and the augmentations and crops built on them now build their sampling grid and sample in float32 and return the input dtype; `homography_warp` with a normalized homography, `HomographyWarper` and the depth, elastic and thin-plate-spline warps sample in float32. On torch 2.5.1, which has no CPU half-precision `grid_sample`, these warps now run instead of raising. Other devices and dtypes are unchanged.
