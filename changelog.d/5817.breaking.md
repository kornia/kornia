`pyrdown` and `PyrDown` now compute the output width with the same rule as the height, `int(width / factor)`, so both axes follow the documented `floor(side / factor)`. The width used floor division of the floating-point values, which could drop a pixel when `width / factor` is a whole number and the factor's binary value lies slightly above its decimal value (1.1, 1.3, 1.6, 1.8, 2.2, ...): at `factor=1.6` a 480 x 640 image used to give 300 x 399 and now gives 300 x 400. Every width that is a multiple of 8 at `factor=1.6`, of 13 at 1.3 or of 9 at 1.8, and some multiples of 11 at 1.1, gains that pixel, and the output values change with the new sampling grid. Integer and dyadic factors (2.0, 3.0, 1.5), KeyNet's internal 1.2 and the default `scale_factor_levels` of `MultiResolutionDetector` (`sqrt(2)`) give the same sizes as before; a `MultiResolutionDetector` configured with an affected `scale_factor_levels` can return different detections.
