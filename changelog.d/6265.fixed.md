`kornia.image.Image` now raises `ShapeError` when an int, float or one-element tensor size in its `ImageLayout` does not match the data. In 0.9.0 the layout check compared the sizes as strings and skipped any that were not all digits, so a tensor, float or negative size was never checked (`CameraModel.scale` returns tensor and float sizes), and `height` and `width` then reported the layout's size instead of the data's. A multi-element tensor size now raises `RuntimeError` when the `Image` is built. The `ShapeError` message, also for data with the wrong number of dimensions, now reads like `Shape mismatch: expected (3, 9, 9), got [3, 4, 5].`

Building an `Image` from `x.shape`, and `depth_from_disparity` with a `(B,)` `baseline` or `focal`, now compile under `torch.compile(fullgraph=True)` with dynamic shapes, including the automatic recompile at a second image or batch size; in 0.9.0 both raised `Unsupported` there. A `(B,)` parameter that does not match the batch now reports `Shape mismatch: expected (2,), got [3].`
