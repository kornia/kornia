`Boxes.filter_boxes_by_area` now marks the boxes it removes as invalid instead of only zeroing their stored inclusive vertices. Previously a removed box exported as `[0, 0, 1, 1]` in the exclusive `'xyxy'`, `'xywh'` and `'vertices'` modes, `to_mask` filled pixel `(0, 0)` for it, and a later `transform_boxes`, `translate` or `pad` moved it like a real box. Now it exports as exact zeros in every mode, also after later transforms, and `to_mask` draws nothing for it. `RandomMosaic` boxes below `min_bbox_size` change in the same way: in direct calls for every box key, and inside `AugmentationSequential` for `"bbox_xywh"`, and for every key when a geometric augmentation follows the mosaic (it used to move them into real-looking boxes; without one, `"bbox_xyxy"` and `"bbox"` already came out as zeros). Because zero-width rows are rejected on import, passing such an `'xyxy'` or `'xywh'` export back to `Boxes.from_tensor` with the default `validate_boxes=True`, or a `"bbox_xywh"` output to another `AugmentationSequential`, now raises `ValueError` where it used to import a 1x1 box at the origin. A `Boxes` object pickled by an earlier version loads with every box valid.
