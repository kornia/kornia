`get_hanning_kernel1d` and `get_hanning_kernel2d` export with torch 2.14's default (dynamo) ONNX exporter again. Built without a `dtype`, the window started from an int64 ramp multiplied by a float, an `aten.mul.Scalar` the exporter has no translation for with onnxscript 0.7.1 (`ConversionError`). The ramp is now built in the default floating dtype; its values are exact integers, so the eager output is unchanged bit for bit.
