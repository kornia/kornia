`equalize_clahe` and `RandomClahe` now spread the residual of the clipped pixels the way OpenCV does, one count on every `max(256 // residual, 1)`-th histogram bin from bin 0, in the fast, per-sample `clip_limit` and differentiable paths. They used to write the residual into the first `residual` bins, which lifted every tile's lookup table: wherever clipping left a residual, the output was brighter than `cv2.createCLAHE`, by about 40 gray levels on average for 64 x 80 to 96 x 96 images with an 8 x 8 grid and clip limit 2.0, and by 4 to 5 levels at 224 x 224. The output now changes for every tile whose clipping leaves a residual (#5654). On the images we measured (64 x 80 to 512 x 512, 8 x 8 grid, clip limits 2, 4 and 40), the mean signed difference from OpenCV is now within 0.1 gray levels in the fast, per-sample and differentiable paths, with the fast paths rounding each lookup-table entry as OpenCV does (#5659). Smooth images in small tiles can still differ by several levels, because kornia blends neighbouring tiles with different weights (#5698).
