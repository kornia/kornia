`to_onnx` keeps the parameters and transformation matrices that augmentations and their containers stored from their last call, so `inverse()` and `transform_matrix` after an export still describe that call. The export's run on its dummy input used to replace them: after a legacy TorchScript export (the default before torch 2.9, `dynamo=False` from it), `inverse()` raised or inverted the dummy's transform. They now come back as the same objects with the same items, also when the export fails, as the `show()` / `save()` output cache now does (#6130). The export also gives back the global random state it drew from, so the draws after it are the ones they would be without it; it removes the global buffer-registration hook that torch 2.9's `torch.export` leaves after a failed trace, which made every later `torch.compile(..., fullgraph=True)` that registers a buffer raise `Unsupported`; and `RandomResizedCrop` no longer stores each call's crop sizes on its generator, where a torch 2.9 dynamo export left a fake tensor that made `deepcopy` and `pickle` raise.
