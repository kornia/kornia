`motion_from_essential_choose_solution` now returns a fourth value, the number of correspondences at positive depth in both cameras for the selected pose candidate, with shape `(B,)` (a 0-d tensor for unbatched inputs), as OpenCV's `recoverPose` does (#4879). Previously it returned `(R, t, points3d)`, and when no correspondence passed the depth test (for example with `mask` all `False`) it returned candidate 0 with nothing to tell the caller. It now returns `(R, t, points3d, num_valid)`, and `num_valid == 0` flags that case. Code that unpacks three values, `R, t, X = motion_from_essential_choose_solution(...)`, must unpack four.
