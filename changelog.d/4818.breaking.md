Morphology no longer uses the finite `max_val` sentinel for floating-point images. Before, a window with no kernel cell inside the image under `border_type="geodesic"` returned a finite value built from `max_val` (for example `-9999.0` from `dilation` with the default `max_val=1e4`), and a cell the kernel excludes still contributed its pixel minus `max_val`, so data of magnitude near `max_val` gave wrong results (`dilation` of `[0, 5e4, 0]` by `[[1, 0, 1]]` returned `40000` in the middle instead of `0`). Now an empty window returns `-inf` from `dilation` and `+inf` from `erosion`, as scipy and scikit-image do; `opening`, `closing`, `gradient`, `top_hat` and `bottom_hat` inherit those infinities; and `max_val` has no effect on floating-point images.
