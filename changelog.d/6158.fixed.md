`MS_SSIMLoss` now requires `img1` and `img2` to be 4-D `(B, C, H, W)` tensors with the same channels, height and width and equal batch sizes, or a batch size of 1 that is compared with every image of the other batch as before, and raises `ValueError` otherwise (a `ShapeError` for a shape mismatch), also with Kornia checks disabled (#6157). It used to compare only the number of dimensions: a height or width of 1 was broadcast and returned a wrong loss, and so did some 3-D `(C, H, W)` pairs. Inputs of different ranks already raised `ValueError`; every other mismatch or input that is not 4-D ended in a torch `RuntimeError` or `IndexError` and now raises `ValueError`.
