`warp_grid`, `warp_grid3d`, `get_translation_matrix2d`, `get_projective_transform` and `get_affine_matrix3d`, and through them `homography_warp` (with the default `normalized_homography=True`), `homography_warp3d` and `HomographyWarper`, now raise a `ShapeError` for an input of an unsupported rank instead of misreading it. An unbatched `(3, 3)` or `(4, 4)` homography used to have its first dimension taken as the batch size and its one matrix applied to every sample, so `warp_grid` returned 3 grids and `homography_warp` worked for exactly 3 images; a `(2,)` translation gave two matrices; a `(3,)` scale was read as `(sx, sy, sz)` shared by every sample, whatever the batch, and a `(B,)` scale, the shape `get_affine_matrix3d` documented, was misread the same way at `B = 3` and failed for any other `B` above 1. Pass one homography per image, `(B, 3, 3)` (`M.expand(B, -1, -1)` shares one matrix across the batch), translations as `(B, 2)`, and scales as `(B, 3)` per axis or `(B, 1)` per sample, with `(1, 3)` for a single `(sx, sy, sz)`. Inputs of the documented shapes are unchanged, except the `(B,)` scale that `get_affine_matrix3d` used to document, which now needs a trailing dimension: `(B, 1)`.
