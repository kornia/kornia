`LightGlue("doghardnet")` and `LightGlue("dog_affnet_hardnet")`, and `LightGlueMatcher` in these modes, now stop early and prune points by default (`depth_confidence=0.95`, `width_confidence=0.99`), as the upstream doghardnet configuration does; they used to run every layer on every point. On 40 Oxford affine pairs with `DoGHardNet(2048)` the matcher runs 1.9x faster on CPU, finds 1.5 % fewer correct matches at 3 px, and estimates homographies as accurately. Pass `depth_confidence=-1, width_confidence=-1` for the previous matches. An architecture keyword argument that contradicts the weights of `features`, such as `LightGlue("disk", input_dim=64)`, used to be ignored and now fails, when the weights load or at the first call, except `n_layers` with `"xfeat"`: more than its 6 layers leaves the extra layers random and the model in training mode, fewer runs a truncated network. A `weights` keyword argument that names another checkpoint than the one of `features`, such as `LightGlue("disk", weights="superpoint_lightglue")`, used to be ignored and now raises: with keyword arguments winning, it would have cached the DISK checkpoint under the SuperPoint file name.
