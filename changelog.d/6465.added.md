`match_snn` and `match_smnn` find the nearest and second-nearest distance of each descriptor with two row reductions instead of `torch.topk`, with the same matches and ratios, nan and infinite distances included. On an Apple M1, given 2048 x 2048 to 8000 x 8000 distance matrices, `match_snn` is 2.3x faster on MPS and as fast as before on CPU, and `match_smnn` is 1.5-1.8x faster on MPS and 1.3x faster on CPU; with the distance computation, `match_snn` and `match_smnn` are 1.2-1.7x faster on MPS. A nearest neighbour tied with another, which only `th >= 1` accepts, is now the first tied descriptor on every device; `torch.topk` gave the last one on CPU for long rows.
