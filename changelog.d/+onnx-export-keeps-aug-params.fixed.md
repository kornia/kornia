`to_onnx` keeps the parameters and transformation matrices that augmentations and their containers stored from their last call, so `inverse()` after an export still inverts that call. The export's run on its dummy input used to replace them: after a legacy TorchScript export (the default before torch 2.9, `dynamo=False` from it), `inverse()` raised or inverted the dummy's transform. They now come back as the same objects, also when the export fails, as the `show()` / `save()` output cache already did.
