`TensorWrapper`, `Vector2`, `Vector3` and `Scalar` results now get one type rule, whether a torch function, a tensor method, a tensor attribute or an operator produced them. A result takes the class of a `Vector2`/`Vector3` operand, on either side, when it ends in that width and keeps that operand's axes. Otherwise it takes the class of the first operand without a width, and otherwise it is a plain tensor. Before, a tensor method such as `v.clone()` returned a plain tensor while `torch.clone(v)` returned a `Vector3`, `Scalar * Vector3` returned a `Scalar` holding the vectors, and `torch.linalg.norm(v, dim=-1)` and `v.T` raised unless the result happened to end in 3, in which case it was returned as a `Vector3`. Now `v.clone()` and `Scalar * Vector3` are a `Vector3`, and `torch.linalg.norm(v, dim=-1)` and `v.T` return plain tensors. The same applies to any torch function that removes an axis: `torch.mean(v, dim=0)` of an `(N, 3)` `Vector3` was a `Vector3` and is now a plain `(3,)` tensor, as `v.mean(dim=0)` already was. `Vector2`/`Vector3` indexing now uses `data[key]`: `v[..., 0]` and `v[:, 0]`, which raised, and an unbatched `v[0]`, which raised `IndexError`, return the plain tensor the wrapped tensor gives, and keys that keep the coordinate axis return the vector class as before.
