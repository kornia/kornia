`SOLD2.match` no longer replaces the global `torch.diag` with a tensor, which made every later `torch.diag(...)` call in the process (including `MKDDescriptor(whitening=...)`) raise `TypeError`. `SOLD2(config=cfg)` no longer sets `use_descriptor = True` on the `DetectorCfg` it is given; it works on a copy. `WunschLineMatcher.needleman_wunsch` now allocates its table in the dtype of the scores; float64 scores used to raise an index_put dtype error, and half-precision scores gave a float32 result. `SOLD2.match` now samples each descriptor map with a grid in that map's dtype, so segments in any floating-point dtype, including the float32 segments `SOLD2.forward` returns, match against the descriptors of a float64 or half-precision model; that, and float64 segments with float32 descriptors, used to raise a `grid_sample` dtype error such as `expected scalar type Half but found Float`.
