`motion_blur` and `MotionBlur` now default to `border_type='reflect'`, and `motion_blur3d` and `MotionBlur3D` to
`'replicate'`; previously all four zero-padded (`'constant'`). The zero padding pulled pixels whose kernel reaches
past an edge toward `0`: a constant image came back as low as `0.6` at the border for `kernel_size=5` at angle 0 in
2-D and `0.667` for `kernel_size=3` at angle `(0, 0, 0)` in 3-D, and lower at other angles and directions (measured
down to `0.2` in both). A constant image now stays constant, as it does under `filter2d`, `gaussian_blur2d`,
`box_blur` and `filter3d`. Pass `border_type='constant'` to keep the old output. `'reflect'` needs each spatial axis
longer than `kernel_size // 2`, so a 2-D image with an axis of `kernel_size // 2` pixels or fewer now raises at the
default border instead of being zero-padded; the 3-D default is `'replicate'` so that thin volumes (`D = 1`) still
work. On torch releases without a float16 CPU `reflection_pad2d` / `replication_pad3d` kernel (2.5.1 among them),
float16 CPU input to these four filters now raises at the default, where it used to run with zero padding; pass
`border_type='constant'` (the old behaviour) or `'circular'` (which needs each axis at least `kernel_size // 2` long)
there. `RandomMotionBlur` and `RandomMotionBlur3D` keep their own `'constant'` default, so their output does not
change.
