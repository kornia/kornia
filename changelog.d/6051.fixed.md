More vision-language fixes in `kornia.models`, following #6044:

- Under float16 or bfloat16 `torch.autocast`, an image whose patches are all masked is pooled by `SigLip2VisionModel`'s attention-pooling head with uniform weights, as without autocast. It pooled to `nan`: the head filled the masked scores with the float32 minimum, which rounds to `-inf` in the autocast dtype. It now fills with the minimum both dtypes can hold.
- `MoonViTAttention`, `MoonViT` and `KimiVLModel` read a `(B, N)` attention mask as a padding mask over each sample's keys, as `SigLip2Attention` does. It went to `scaled_dot_product_attention` as an `N x N` query x key mask: a batch size other than 1 and `N` raised a size mismatch, and `B == N` masked query rows by batch index.
- `MoonViTAttention` again broadcasts a 3-D mask whose leading dimension is not the batch size, such as a per-head `(H, N, N)` mask of a batch of one, against the `(B, H, N, N)` attention scores. #6044 made it raise: it read every 3-D mask as `(B, N, N)`.
- `NaFlex` warns, naming `patch_size`, when it reads a `(B, N, C)` patch output without `patch_size` as a square grid that takes rectangular patches: 256 tokens of a `128 x 512` image, the `8 x 32` grid of #6004 at patch 16, are read as `16 x 16`. It added the table in that layout silently. A rectangular patch embedding gets the same warning, and `patch_size` silences it.
- The `RuntimeError` of `SigLip2Builder.from_pretrained_hf` for a checkpoint that does not fit the configuration read from its name gives that configuration (hidden size, layers, heads, patch size, image size, vocabulary).
