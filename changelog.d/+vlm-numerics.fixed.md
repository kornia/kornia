The vision-language models of `kornia.models` follow their reference implementations in more places:

- `SigLip2Model(..., return_loss=True)` returns SigLIP's pairwise sigmoid loss over every image-text pair of the batch, with the matching pairs labelled +1 and every other pair -1. It used only the matching pairs, so the negatives never entered and the loss fell to zero as `logit_bias` grew: `0.0` on a batch of 4 with `logit_bias = 10`, where SigLIP's loss is `38.54`.
- The `attention_mask` of `SigLip2VisionModel` and `SigLip2Model.get_image_features` reaches the attention-pooling head as well as the encoder, so the pixels of masked patches no longer change the pooled embedding. For a `(B, N, N)` or `(B, 1, N, N)` mask, the head leaves out the patches no query may attend to.
- SigLip2's MLPs use the tanh approximation of GELU (`hidden_act="gelu_pytorch_tanh"`, the new config default) and `SigLip2ImagePreprocessor` resizes bilinearly by default, as the SigLIP 2 checkpoints do (`"resample": 2` in their `preprocessor_config.json`). Both used exact GELU and bicubic resizing. `SigLip2ImagePreprocessor` and its `from_config` take `interpolation="bicubic"` for the SigLIP 1 checkpoint `google/siglip-base-patch16-224`.
- `NaFlex` resizes its position table to the image's patch grid whenever that grid is not the table's own square grid, with antialiased bilinear interpolation as transformers' SigLIP 2 does. It added a table unresized in raster order whenever the patch count matched (4.27 off for an 8 x 32 grid and a 16 x 16 table), read a `(B, N, C)` patch output as a square grid (silently wrong for a 128 x 512 image, an error for 192 x 336), and did not antialias a downsampled axis (0.81 off). A float16 or bfloat16 table on the CPU is resized in float32. A position table passed as an `nn.Parameter` stays a parameter of the module and is trained with it; it was registered as a buffer.
- `KimiVLModel` and `MoonViT` apply a `(B, N, N)` attention mask per sample, shared by the heads. The mask's leading dimension lined up with the attention heads: outputs were wrong when the batch size equalled the number of heads, and other batch sizes raised.
- `PaliGemma` follows Gemma: the text embeddings are scaled by `sqrt(hidden_size)`, the embedding's padding row is the new `PaliGemmaConfig.pad_token_id` (default 0) instead of `ignore_index`, the MLP uses tanh GELU, and `GemmaRMSNorm` multiplies by `1 + weight` in float32 before casting. `ignore_index = -100` wrapped to row `vocab_size - 100`, a real token whose embedding was zeroed and received no gradient.
- `SigLip2Builder.from_pretrained_hf` raises `ValueError` before downloading anything for a name outside its supported list; it downloaded the checkpoint and then failed in `load_state_dict` with a shape mismatch.
