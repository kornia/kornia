`laplacian`, `Laplacian`, `get_laplacian_kernel2d` and `get_laplacian_kernel1d` now reject a kernel size of 1 (`1`, or `(1, 1)` for the 2D forms) with an error that says why. A 1x1 Laplacian kernel is `[[0.0]]`, so the default `normalized=True` divided by zero and returned an all-NaN image, and `get_laplacian_kernel2d(1)` and `get_laplacian_kernel1d(1)` returned the all-zero kernel. Sizes such as `(1, 3)` and `(3, 1)`, which are a 1-D second difference, still work. `Laplacian` now validates `kernel_size` when it is constructed (odd, positive, the right length, not 1x1), so an invalid size such as `Laplacian(2)` raises there instead of at the first `forward` call.
