`transform_points` raises a `ValueError` for a transformation batch with several axes, `(*, D+1, D+1)`, that does not line up with the leading batch axes of the points once its size-1 axes are left out. Such a batch used to be paired with the point sets by count, which returned points transformed by the wrong matrices, for example `(2, 2)` matrices with `(2, 4, N, D)` points, or failed inside `bmm`. Batches that line up, such as `(B, 1)` or `(1, B)` with `(B, C, N, D)` points, give the same results as before. Four layouts that main paired correctly only by coincidence now raise too, such as `(1, 2)` matrices with `(1, 1, 2, N, D)` points; give the matrix batch the same axes as the points, `(1, 1, 2)`, instead.
