`find_essential` solves in float64 whatever the input dtype, so a float32 five-point sample no longer misses the true essential matrix (#4884); MPS, which has no float64, solves on the host and copies the candidates back. It now runs on MPS, where `torch.linalg.eigvals` raised `NotImplementedError` (#4528), and on float16 and bfloat16 inputs. On 42000 exact five-point samples with random motions it misses the true matrix by more than 1e-3 12 times, where it missed it 31 times. Its roots come from the host for every device, detached, with a Newton step that supplies their gradient, so `backward` no longer raises at a multiple root (#4903) nor returns NaN gradients for samples without parallax (#4952), and repeated calls on CUDA return identical results. A five-point sample whose constraints are rank deficient, such as one with a repeated correspondence, returns ten NaN candidates and a zero gradient. At 2048 samples it takes 29 ms instead of 40 ms on CPU and 21 ms instead of 28 ms on CUDA; at 256 samples it costs about the same on CPU and 1 ms more on CUDA.
