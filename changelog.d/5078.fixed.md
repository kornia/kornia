`find_essential` solves in float64 (float32 on MPS) whatever the input dtype, so a float32 five-point sample no longer misses the true essential matrix (#4884), and takes the null space of five points from a Householder QR: on 2000 exact samples with random motions every candidate set now contains the true matrix within 1e-4, where the SVD missed it twice. Its roots come from the host for every device, detached, with a Newton step that supplies their gradient, so `backward` no longer raises at a multiple root (#4903) nor returns NaN gradients for samples without parallax (#4952), and repeated calls on CUDA return identical results. A five-point sample whose constraints are rank deficient, such as one with a repeated correspondence, returns ten NaN candidates and a zero gradient. At 2048 samples it takes 29 ms instead of 40 ms on CPU and 21 ms instead of 28 ms on CUDA; at 256 samples it costs about the same on CPU and 1 ms more on CUDA.
