`validate_bbox`, and `validate_bbox3d` for a non-finite coordinate, emit a `FutureWarning` when they return `False`: a future release raises `AssertionError` instead, as `validate_bbox3d` already does for other invalid boxes. Both validators now synchronize with the device once per call, which roughly halves their cost on MPS and speeds up `infer_bbox_shape3d` and `bbox_to_mask3d`.
