`rotation_matrix_to_quaternion` no longer adds `eps` inside the square root of the dominant component, which inflated every `float64` result: the identity used to return `[1.0000000012499999, 0, 0, 0]` and now returns exactly `[1, 0, 0, 0]`, and the unit-norm error of random rotations drops from about `2.5e-9` to about `7e-16`. `eps` is now only a floor on the radicands of the discarded branches; the selected branch's radicand is at least `1` for any real 3x3 matrix, so it never reaches the floor. `ARKitQTVecs_to_ColmapQTVecs` inherits the fix. `float32`, `float16` and `bfloat16` outputs are unchanged.
