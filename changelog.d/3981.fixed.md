`rotation_matrix_to_quaternion` no longer adds `eps` inside the square root of the dominant component, which inflated every `float64` result: the identity used to return `[1.0000000012499999, 0, 0, 0]` and now returns exactly `[1, 0, 0, 0]`, and the unit-norm error of random rotations drops from about `2.5e-9` to about `7e-16`. `eps` is now only a floor on each radicand, applied by safe-argument substitution so gradients stay finite, including at the exactly-zero radicands of discarded branches in `float16` and `bfloat16`. `ARKitQTVecs_to_ColmapQTVecs` inherits the fix. `float32`, `float16` and `bfloat16` outputs are unchanged.
