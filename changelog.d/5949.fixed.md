`homography_warp` (both `normalized_homography` modes), `HomographyWarper`, `homography_warp3d` and
`warp_perspective3d` now return the same image for `s * H` as for `H`. A homography and any nonzero multiple
of it describe the same projective map, but the sampling grid built by `warp_grid`/`warp_grid3d` passed points
with `|w| <= 1e-8` to `grid_sample` undivided, so the arbitrary scale of the matrix changed the output: for a
homography with entries between 0.01 and 1, `1e-8 * H` differed from `H` by up to 0.50 of the image range in
float64, with no NaN and no error. The grid matrices are now divided by a detached projective scale toward
unit magnitude, the same gauge #5752 introduced for `warp_perspective`, so gradients keep the
`dL/d(s*H) = (dL/dH)/s` rule and matrices already in range (`M[2, 2] = 1`) are unaffected bit for bit.
