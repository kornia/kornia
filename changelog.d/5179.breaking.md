`Resize`, `LongestMaxSize`, `SmallestMaxSize` and slice-mode `RandomResizedCrop` with `align_corners=False` and bilinear or bicubic resampling now record the half-pixel map their resize samples with, `x' = (x - x0 + 0.5) * W_out / W_crop - 0.5` and likewise for `y`, as `transform_matrix`, where `x0` and `W_crop` are the crop's first column and width (`0` and the input width for the resize classes). They used to record the corner-to-corner map `x' = (x - x0) * (W_out - 1) / (W_crop - 1)`, so keypoints and boxes moved through `AugmentationSequential` landed up to `|W_out / W_crop - 1| / 2` output pixels from the content they annotate (half a pixel at a 2x upscale), and the `inverse()` of the three resize classes warped the image back with that map, which did not return content to its original place. The resized images, `align_corners=True` (the default for these classes), nearest resampling and resample-mode crops are unchanged.
