Some vision-language calls of `kornia.models` that ran now raise:

- `SigLip2Config.from_name` and `SigLip2Builder.from_name` raise `ValueError` for a name outside the supported list (`google/siglip-base-patch16-224` and the seven `google/siglip2-{base,large}-patch16-{224,256,384,512}` checkpoints). They parsed the name by substrings and returned a base-size configuration, or a model built from it, with the wrong vocabulary or patch size: `google/siglip2-so400m-patch14-384` gave a base model with patch 16, and `google/siglip-large-patch16-256` the SigLIP 2 vocabulary. The supported names give the checkpoints' 64 text positions where they gave 512, so a model built from a name takes at most 64 tokens.
- SigLip2 honours `hidden_act`: `"gelu_pytorch_tanh"` and `"gelu_new"` give tanh GELU, `"gelu"` exact GELU, and any other value raises `ValueError` when the model is built. `hidden_act` was ignored (every MLP used exact GELU), so a config with `hidden_act="quick_gelu"` or `"relu"` built and ran.
- The legacy TorchScript ONNX exporter (`torch.onnx.export(..., dynamo=False)`) raises `UnsupportedOperatorError` for a `NaFlex` whose patch grid is smaller than its position table along an axis, because that table is now resized with antialiasing (`aten::_upsample_bilinear2d_aa`). It exported a plain bilinear resize, which gave wrong values for such grids. The dynamo exporter (`dynamo=True`) exports the antialiased resize, and the legacy exporter still exports grids at least as large as the table along both axes.
