`CenterCrop3D` and `RandomCrop3D` now report invalid crop sizes with the `size` argument and supplied value. Malformed size sequences raise `TypeError` instead of an indexing or internal tensor-shape error; `CenterCrop3D` rejects tuples with extra elements rather than silently ignoring them, so pass exactly `(D, H, W)`. Oversized crops now raise `ValueError` in both classes (previously `AssertionError` in `CenterCrop3D`) and report the requested and input spatial sizes. `CenterCrop3D(n)` remains supported; `RandomCrop3D(n)` remains unsupported and requires `(n, n, n)`.
