`RandomMotionBlur` now draws every odd size in a `kernel_size` range with equal probability, the upper bound included. Previously the upper bound was practically never drawn (only when a float32 draw rounded onto it), so `kernel_size=(3, 5)` practically always blurred with `3` and `(3, 7)` drew practically only `3` and `5`. An even upper bound caps at the largest odd size below it, and a range holding no odd size still rounds up, so `(4, 4)` draws `5` as before. Because the larger sizes are now drawn, `kernel_size=(3, 5)` with `border_type="reflect"` on a `2 x 2` image raises for roughly half the draws, where the constant `3` always fit. A two-element list such as `kernel_size=[3, 9]` is now accepted as a range, like a tuple, instead of raising `TypeError`.
