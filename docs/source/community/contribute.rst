Contribute
==========

.. meta::
   :description: How to contribute to Kornia: report a bug with a reproducible example, ask questions on GitHub Discussions or Discord, and send code or documentation following the contributing guide.

We develop Kornia for ourselves and the computer vision community. If the library is useful to you, you are
welcome to help in whatever way suits you — every section below is a valid contribution.

Report a bug
------------

Open an issue on the `GitHub issue tracker <https://github.com/kornia/kornia/issues/new/choose>`_. The most
useful reports come with a minimal reproducible example and the environment line the bug template asks for
(kornia, PyTorch and Python versions, OS, device backend). Please preview and redact anything private before
posting.

Ask questions
-------------

Usage questions and ideas belong in `GitHub Discussions <https://github.com/kornia/kornia/discussions>`_,
or on `Discord <https://discord.gg/HfnywwpBnD>`_ if you prefer chat. Check the :doc:`FAQ <faqs>` and the
:doc:`conventions page </get-started/conventions>` first — many "bugs" are convention mismatches.

Contribute code
---------------

Code and documentation contributions go through pull requests on `GitHub
<https://github.com/kornia/kornia>`_. The `contributing guide
<https://github.com/kornia/kornia/blob/main/CONTRIBUTING.md>`_ describes the development setup, the social
contract and the technical guidelines; the repository's ``AGENTS.md`` documents the day-to-day commands
(tests, lint, docs builds). Maintainers review and respond when they can, but we cannot promise that every
issue or pull request will be reviewed or merged.

Not sure where to start? Documentation fixes, new tests and issues labeled `"good first issue"
<https://github.com/kornia/kornia/issues?q=is%3Aissue+is%3Aopen+label%3A%22good+first+issue%22>`_ are the
friendliest entry points. And if code is not your thing, consider :doc:`sponsoring <sponsor>` instead.
